# 统一通知服务 API - 需求文档
# 版本: 1.0
# 日期: 2026-08-20

REQ-001: 通知发送功能 - 支持短信(SMS)、邮件(EMAIL)、推送(PUSH)三种渠道发送通知，发送前需对必填参数（用户ID、渠道类型、通知内容）进行校验，参数不合法时返回明确的错误信息。

REQ-002: 幂等去重机制 - 相同用户、相同渠道、相同内容在60秒时间窗口内不得重复发送，系统应自动识别并拦截重复请求，返回已发送记录的状态信息。

REQ-003: 用户级限流 - 每个用户每分钟最多发送10条通知，超出限流阈值时拒绝请求并返回限流提示信息，限流窗口按自然分钟计算。

REQ-004: 模板管理 - 提供通知模板的增删改查(CRUD)功能，支持模板变量替换（如 ${username}、${code}），模板创建时需校验模板语法的合法性，模板内容不得超过500字符。

REQ-005: 发送历史查询 - 支持按用户ID、渠道类型、时间范围等条件查询发送历史记录，查询结果需支持分页展示，每页默认20条，最大不超过100条。

REQ-006: 批量发送与进度跟踪 - 支持批量发送通知，单次批量不超过100条，批量任务需返回任务ID用于跟踪发送进度，支持查询批量任务的完成状态（已处理/总数）。

REQ-007: 回调处理 - 支持接收第三方渠道的投递状态回调（成功/失败/超时），根据回调结果更新通知的投递状态，回调数据需进行签名验证。

REQ-008: 黑名单管理 - 支持黑名单的添加、移除、查询功能，发送通知前需自动检查目标用户是否在黑名单中，黑名单中的用户不得收到任何通知。

REQ-009: 重试机制 - 发送失败的通知需支持自动重试，最多重试3次，重试间隔采用指数退避策略（第1次1秒、第2次2秒、第3次4秒），超过最大重试次数后标记为最终失败。

REQ-010: 统计功能 - 提供通知发送的统计信息，包括发送成功率、各渠道（SMS/EMAIL/PUSH）的发送数量分布，统计维度支持按天/周/月查询。
