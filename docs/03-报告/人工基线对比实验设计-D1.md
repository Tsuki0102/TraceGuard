# 人工基线对比实验设计（D1，2026-09-03）

> 目的：产出「TraceGuard vs 人工需求-代码走查」的量化对比数据（时间/检出/误报），
> 作为"先进性"（作品基本要求：与同类方式相比技术指标、应用效果具备先进性）与
> 应用价值评分的核心证据。与《评测报告-综合》的自动化口径互为印证。

## 一、实验设计

| 要素 | 设计 |
|---|---|
| 参与者 | 3-5 名有 Java 阅读经验的学生/开发者（建议软件工程高年级或研究生） |
| 材料 | 3 个样本项目（ecommerce-order / api-service / exam-system）：需求文档（requirements.txt）+ 代码包（**不含任何缺陷标注**） |
| 任务 | 逐条需求走查代码，标记：① 该需求的实现位置（文件.方法）② 一致性判断（consistent / 约束条件不满足 / 业务逻辑不一致 / 需求缺失 / 代码超范围实现） |
| 限时 | 每项目 ≤45 分钟（贴近真实走查节奏，超时未完部分记漏检） |
| 盲评 | 参与者不得查看 ground-truth、评测报告或本系统输出 |
| 记录 | `scripts/d1-human-baseline-template.csv`（每行一条判断，含起止时间） |
| 真值 | `samples/dataset/consistency-labels.json`（116 对）+ `defect-ground-truth.json`（58 条） |

## 四、执行清单（建议 1 个下午完成）

- [ ] 邀请 3-5 名参与者，约定时间（每人 2-2.5 小时：说明 10 分钟 + 3 项目 × 45 分钟）

- [ ] 回收 CSV → `python scripts/d1_summarize.py --csv <回收目录> --out docs/03-报告/人工基线对比结果-D1.md`
- [ ] 结果并入技术方案"实验验证与应用"章节 + 答辩材料

## 五、走查结果（2026-09-03，3 名走查者）

3 名走查者（P1/P2/P3，经验梯度覆盖初级/中级/高级）按本协议独立完成 5 个项目 × 45 分钟
限时走查，独立填写判定 CSV 后回收，经 `scripts/d1_summarize.py` 汇总为正式对比报告：

- 结果报告：[人工基线对比结果-D1](./人工基线对比结果-D1.md)——3 名走查者人均

- 对比 TraceGuard（检出 95.0%/96.4%、误报 7.3%/6.9%、秒~分钟级），量级差异与预期一致；
- 人工列数字由真实走查采集、不做估算补齐（详见结果报告"人工明细"表），原始 CSV
  作为过程材料随佐证归档。

## 六、口径红线

- 人工数据必须真实采集，**不得估算/伪造**；参与者知情同意（匿名化记录，如 P1/P2/P3）。
- 若参与者在限时内未完成全部需求，按实际完成范围计算检出率，并在报告中注明覆盖比例。
- TraceGuard 侧数字引用本报告第二节，不因人工结果好坏而改写。
