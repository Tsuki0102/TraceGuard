## 5. 增强模式基准（FUN-06，待目标机执行）

> 上述达标结论均为**规则模式**（llm.enabled=false、embedding 跳过）。SRS 性能指标未区分模式，
> 开启 LLM/Embedding 增强后的耗时需单独实测留档，避免结项答辩被质疑。

### 5.1 基准方法

- 同一 PerformanceTest（`eval.PerformanceTest`）可跑增强模式：
  - **本地 BGE Embedding 开启**：`traceguard.llm.embedding.provider=local`，`model-path` 指向下载的 ONNX 模型
    （执行 `scripts/download_bge_model.sh` 下载并写入 .env，或直接配置 `EMBEDDING_MODEL_PATH`）；
  - **本地 CodeLlama 开启**：`traceguard.llm.engine=langchain` + `provider=codellama`（需 Ollama，见 FUN-03）。
- 每次跑 kilo 级 3 次取中位数，结果写入 `性能基准报告-{kilo|tenk}.md` 的"增强模式"分节。

| 模式 | 状态 | 说明 |
|---|---|---|
| 规则模式 | ✅ 已实测 | kilo 5.086s / tenk 139.935s（见第 3 节） |
| 本地 BGE 增强 | ✅ 已实测（kilo） | 模型已下载并验证（FUN-04①）；kilo 增强模式 **13.394s** 达标，`embedSemantics` 6.84s 占 51%，本地向量化不构成瓶颈（明细见 性能基准报告-kilo.md） |
| 本地 CodeLlama 增强 | 🔶 端到端已验证 / 性能耗时待测 | Ollama + `codellama:7b` 已就绪，CodeLlama×LangChain 一致性判定端到端评测成功（LLM 成功 54/55=98.2%，见 FUN-03/评测报告）；该模式下完整性能基准（每任务含 LLM 一致性判定）耗时待单独批次回填 |

**结论**：增强模式基准的方法与配置已齐备，受限于外部模型/算力资源未在本机实测；
规则模式（主验收口径）已达标且远优于阈值。建议结项前于目标机补齐 5.1 两个增强批次并回填。
