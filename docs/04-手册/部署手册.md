# TraceGuard 部署手册（V1.2）

> 对应 SRS 7.3 成果验收「部署手册」要求。本文档说明 Windows 原生与容器两种部署形态，覆盖环境准备、数据库初始化、构建、启动、生产加固与分发安装包。

---

## 1. 环境要求

| 组件 | 版本 | 说明 |
|---|---|---|
| JDK | 21+ | 后端编译与运行（编译目标 java.version=21） |
| Maven | 3.8+ | 后端构建 |
| MySQL | 8.0+ | 业务数据库（utf8mb4） |
| Node.js | 20 LTS+ | 前端构建/预览 |

| 可选 | Ollama + qwen2.5-coder | 本地 LLM 增强（默认关闭，规则模式即可运行；实测模型 `qwen2.5-coder:14b`，LLM 判定成功率 100%） |

## 2. 部署方式一：Windows 一键部署（推荐，AUD-12）

### 2.1 前置安装
JDK 21+、Maven 3.8+、MySQL 8.0+、Node.js 20 LTS+ 均加入系统 Path。

### 2.2 执行部署脚本
在项目根目录打开 PowerShell：
```powershell
powershell -ExecutionPolicy Bypass -File scripts\deploy-windows.ps1 -MysqlUser root -MysqlPass '你的密码'
```
脚本按序完成（幂等可重跑）：
1. 前置检查（Java/MySQL/Node/Maven）
2. 数据库初始化（`init.sql`，库已存在则跳过，启动时空表由幂等迁移补齐）
3. 后端构建（`mvn -B package -DskipTests`）
4. 前端构建（`npm ci && npm run build`）
5. 生成启动脚本（`start-backend.bat` / `start-frontend.bat` / `start-all.bat`）

### 2.3 启动
双击 `start-all.bat`，并行拉起前后端并打开浏览器；或分别双击 `start-backend.bat` / `start-frontend.bat`。
- 后端：`http://localhost:8080/api`（prod 配置，日志 `logs/traceguard.log`）
- 前端：优先 nginx（`frontend\nginx-windows.conf`，端口 80）；未安装 nginx 自动降级 `npx vite preview --port 3000`
- 访问 `http://localhost:3000`（或 nginx 的 `http://localhost`），默认账号 `admin / admin123`（登录后请尽快修改）

### 2.4 常用参数
| 参数 | 说明 | 默认 |
|---|---|---|
| `-MysqlUser` | MySQL 用户名 | `root` |
| `-MysqlPass` | MySQL 密码（缺省交互提示） | 空 |
| `-SkipBuild` | 跳过构建仅生成脚本 | 关闭 |

### 2.5 版本升级与新增运行参数（V1.1.1，2026-09）
- **Schema 增量**：升级既有库无需手工迁移——重新执行一次 `init.sql` 即幂等补齐（新增 `tg_code_unit.content_hash` 与索引 `idx_project_file`、`tg_defect.risk_signals`，存量数据零改动；新增列由后续分析任务自动填充）。
- **新增运行参数**（`application.yml`）：
  | 参数 | 说明 | 默认 |
  |---|---|---|
  | `traceguard.analysis.incremental-code` | 代码增量解析开关（false=强制全量） | `true` |
- **新增系统配置键**：`risk_weights`（规则信号权重，阈值实验室保存/热更新；未配置时用内置网格实证基线）。

## 3. 部署方式二：Docker Compose

仓库提供 `docker-compose.yml`，容器化部署（与 Windows 脚本并存，互不影响）：
```bash
docker-compose up -d --build
```
后端容器暴露 `8080`，前端由 nginx 容器托管，数据库使用配套 MySQL 服务或外部 MySQL。

#### 3.1 数据库迁移机制说明（DOC-09）

- **当前机制**：建库建表由 `backend/src/main/resources/sql/init.sql` 幂等 DDL 完成（`CREATE DATABASE IF NOT EXISTS` / `CREATE TABLE IF NOT EXISTS`，启动时由 `StartupDbCheck` 校验/补齐），**Windows 单机/单副本部署无并发竞态**。
- **已知限制**：多实例/多副本**并发启动**时，多进程同时执行动态 DDL 存在低概率竞争（建表/索引重复等）。
- **规划（中期）**：引入 **Flyway** 管理增量迁移——`V1__init.sql` 基线 + `V2__*.sql` 增量脚本，以 `flyway_schema_history` 保证版本顺序与幂等，多副本由迁移锁串行化；切换后不再手工执行 `init.sql`（基线由 Flyway 接管）。实施前需与现有 `init.sql` 做兼容性核对。

## 4. 生产加固

正式部署前设置环境变量（避免内置默认密钥）：
- `JWT_SECRET`：JWT 签名密钥
- `STORAGE_ENCRYPT_KEY`：上传文件加密存储密钥
- `BACKUP_ENCRYPT_KEY`：备份文件 AES-256-GCM 加密密钥

可通过 `application-prod.yml` 或环境变量 `MYSQL_USER` / `MYSQL_PASSWORD` / 连接串覆盖数据库连接。

### 4.1 第三方工具集成配置（Jira / 禅道 / 企业微信 / 钉钉，可选）

> **默认状态说明**：`application.yml` 中四个工具默认 `enabled=true`，但 base-url / 凭据均为**演示占位值**（demo 域名与示例 token），仅用于连通性演示。生产部署必须通过环境变量覆盖为真实服务地址与凭据（或显式设 `enabled=false` 关闭），否则会向演示端点发起请求。

| 工具 | 环境变量 | 说明 |
|---|---|---|
| Jira | `JIRA_BASE_URL` | Jira 服务地址，如 `https://your-jira.example.com` |
| Jira | `JIRA_USER` | 用户名 |
| Jira | `JIRA_TOKEN` | API Token |
| Jira | `JIRA_PROJECT_KEY` | 项目 Key（如 `DEMO`） |
| 禅道 | `ZENTAO_BASE_URL` | 禅道服务地址 |
| 禅道 | `ZENTAO_TOKEN` | API Token |
| 禅道 | `ZENTAO_PRODUCT_ID` | 产品 ID |
| 企业微信 | `WECOM_BASE_URL` | 企业微信 API 地址（默认官方域名；演示/内网可覆盖为 mock） |
| 企业微信 | `WECOM_KEY` | 群机器人 Webhook Key（如 `693axxx-xxxx`） |
| 企业微信 | `WECOM_SECRET` | 机器人加签密钥（开启"加签"时必填，可选） |
| 钉钉 | `DINGTALK_BASE_URL` | 钉钉开放平台地址（默认官方域名；演示/内网可覆盖为 mock） |
| 钉钉 | `DINGTALK_TOKEN` | 自定义机器人 AccessToken |
| 钉钉 | `DINGTALK_SECRET` | 机器人加签密钥（开启"加签"时必填，可选） |
| 入站同步 | `INBOUND_SYNC_ENABLED` | 远程状态→本地缺陷回写轮询开关（默认 `true`，无需公网地址） |
| 入站同步 | `INBOUND_SYNC_CRON` | 轮询 cron（默认 `0 */5 * * * *` 每 5 分钟；演示可改 `*/20 * * * * *` 每 20 秒） |

覆盖方式：启动后端时追加参数，例如（覆盖为真实服务配置，`enabled` 已默认开启演示配置）
```powershell
java -jar backend\app\traceguard-backend-*.jar --spring.profiles.active=prod `
  --traceguard.integration.jira.enabled=true `
  --traceguard.integration.jira.base-url=http://localhost:18080 `
  --traceguard.integration.jira.username=admin `
  --traceguard.integration.jira.token=xxxx `
  --traceguard.integration.jira.project-key=DEMO `
  --traceguard.integration.zentao.enabled=true `
  --traceguard.integration.zentao.base-url=http://localhost:18081 `
  --traceguard.integration.zentao.token=xxxx `
  --traceguard.integration.zentao.product-id=1 `
  --traceguard.integration.wecom.enabled=true `
  --traceguard.integration.wecom.base-url=https://qyapi.weixin.qq.com `
  --traceguard.integration.wecom.key=xxxx `
  --traceguard.integration.wecom.secret=xxxx `
  --traceguard.integration.dingtalk.enabled=true `
  --traceguard.integration.dingtalk.base-url=https://oapi.dingtalk.com `
  --traceguard.integration.dingtalk.access-token=xxxx `
  --traceguard.integration.dingtalk.secret=xxxx
```
启用后在「系统设置 → 集成连通测试」可查看四工具的配置摘要并测试连通；Jira/禅道可在需求/缺陷页导出 Issue / 推送 Bug，企微/钉钉可发送 Webhook 通知（测试连通即发送一条测试消息）。详见《用户操作手册》13.7。

## 5. 可分发安装包（3.7 整改 + 安装程序）

提供两种面向最终用户的软件分发形态，目标机均**无需自备 Maven / Node**。

### 5.1 一键安装向导（推荐，自包含）
适合无构建环境、希望"双击即用"的目标机。
```powershell
# 先构建产物（或用手头已构建好的 backend jar + frontend/dist + init.sql）
powershell -ExecutionPolicy Bypass -File scripts\deploy-windows.ps1
# 生成安装源（installer-staging）与可选 exe 安装包
powershell -ExecutionPolicy Bypass -File scripts\build-installer.ps1
```
安装源 `installer-staging/` 含：
- `backend/app/traceguard-backend-*.jar`、`backend/init.sql`
- `frontend/dist/`、`frontend/nginx-windows.conf`
- `install.ps1` / `install.bat`（一键安装向导）

最终用户操作：
1. 将 `installer-staging/` 拷贝到目标机，双击 `install.bat`；
2. 向导自动：选安装目录 → 探测/拉取便携 JRE 21 + MySQL 8.0 + nginx 到 `runtime\` → 初始化数据库与建表 → 生成启动器 → 创建桌面/开始菜单快捷方式 → 可选注册 Windows 服务；
3. 安装完成访问 `http://localhost:80`（默认账号 `admin / admin123`）。

> 运行时组件在首次安装时按需从官方源下载便携版（带离线兜底：下载失败可手动将对应 zip 解压到 `runtime\<jre|mysql|nginx>\` 后重跑）。如需离线全量包，提前预置运行时至 `runtime\` 即可。

### 5.2 标准 exe 安装包（Inno Setup）
若本机已安装 Inno Setup 6+，`build-installer.ps1` 会自动编译 `scripts/TraceGuard.iss`，产出：
- `installer-out/TraceGuard-Setup-<version>.exe` —— 向导式安装程序（含开始菜单/桌面快捷方式、卸载程序），安装完成后自动运行 5.1 的初始化向导。

未安装 Inno Setup 时，仅输出 `installer-staging/`，可 zip 分发；安装 IS：`winget install JRSoftware.InnoSetup`。

### 5.3 免安装 zip 分发包（兼容旧形态）
```powershell
powershell -ExecutionPolicy Bypass -File scripts\package-dist.ps1
```
产出 `dist-release/TraceGuard-<version>.zip`（含运行包 + init.sql + dist + 启动脚本 + 联动生成的安装器）。目标机需自备 JDK 21+ / MySQL 8.0+，按 `RELEASE_NOTES.txt` 启动。

### 6.6 演示日风险预案

- **LLM 供应商不可用/限流**：演示口径以规则引擎为主（默认开启、秒级完成）；
  LLM 增强口径用本地 Ollama（`codellama`/`qwen2.5-coder`）兜底，或展示 demo-seed
  预置的真实历史任务结果，避免现场依赖外部网络。
- **演示数据被改乱**：执行 6.4 复位 + 6.3 重新生成，2 分钟内恢复。
- **GAP-046 候选复核**：LLM 模式默认按候选复核运行（上限 200 对），万行级
  二审预算约 7 分钟，演示不会出现长时间无响应。
- **演示就绪证据**：《演示全链路巡检报告-C1C2》（docs/03-报告/）12 项巡检全绿
  （分析→判定溯源→五类导出→缺陷闭环），录制演示视频前建议按其清单再彩排一遍。

## 7. 常见问题

- **端口占用**：改 `application-prod.yml`（`server.port`）与 `vite.config.js`（`server.port`）。
- **数据库连接失败**：确认 MySQL 已启动、密码正确、库已建（`CREATE DATABASE traceguard` + 执行 `init.sql`）。
- **LLM 功能不可用**：默认关闭，属正常；启用见 README「大模型配置」一节。
- **强制改密**：管理员新建/重置密码后，用户首次登录会被强制跳转改密页，未改密不可进入业务（GAP-027）。
