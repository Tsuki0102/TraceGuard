# 评审快速体验指南（10 分钟导览）

> 面向大赛评审专家：按本文档可在 10 分钟内完成 **安装 → 登录 → 分析 → 看报告** 全流程体验。
> 全程使用真实分析链路，无任何预置伪造数据（演示数据由真实 REST API 分析生成）。

---

## 〇、环境要求

| 方式 | 操作系统 | 前置依赖 |
|---|---|---|
| A. Docker 一键部署 | Win10/11、macOS、Linux | Docker Desktop（或 Docker Engine + Compose v2） |
| B. Windows 一键部署 | Win10/11 | JDK 21、Maven 3.8+、Node.js 20、MySQL 8.0 |
| C. 安装包（免环境） | Win10/11 | 无（目标机按需拉取便携运行时，支持离线兜底） |

---

## 方式 A：Docker 一键部署（推荐，约 3 分钟）

```bash
# 1) 准备密钥配置（4 个密钥必填，缺失将拒绝启动；可用 openssl rand -hex 32 生成）
cp .env.example .env
#    编辑 .env，填写：JWT_SECRET / STORAGE_ENCRYPT_KEY / LLM_CONFIG_KEY / BACKUP_ENCRYPT_KEY

# 2) 一键启动（前端 80 端口、后端 8080 端口、MySQL 8.0 自动就绪）
docker compose up -d

# 3) 等待就绪（backend healthcheck 通过后 frontend 才启动，约 1-2 分钟）
docker compose ps
```

## 方式 B：Windows 一键部署（本机开发/演示机）

```powershell
powershell -ExecutionPolicy Bypass -File scripts\deploy-windows.ps1 -MysqlUser root -MysqlPass '你的MySQL密码'
# 自动完成建库、构建、生成启动脚本；详见《部署手册》第 4 章
```

## 方式 C：安装包分发（评审机无开发环境时）

```powershell
# 构建机（一次性）：
powershell -ExecutionPolicy Bypass -File scripts\build-installer.ps1
# 产出 installer-staging\（可 zip 分发）与 TraceGuard-Setup-<版本>.exe（Inno Setup 安装包）
# 目标机：双击 install.bat（或安装包 exe）→ 跟随向导完成，详见《部署手册》第 5 章
```

# 前置：系统已按上述任一方式启动。脚本自动：登录演示账号 → 创建项目 → 上传电商订单

## 二、10 分钟体验路径

| 步骤 | 位置 | 看什么 |
|---|---|---|
| 1. 登录 | `http://localhost`（账号 `demo` / `demo12345`） | JWT 认证、角色权限 |
| 2. 项目详情 | 「项目管理」→ 打开「电商订单演示项目」 | 需求文档与代码工程双视图 |
| 3. 一致性结果 | 打开分析任务 | 需求-代码**对齐矩阵**：匹配对三维相似度、一致/缺陷判定、**判定溯源**（每对可查证据链） |
| 4. 缺陷列表 | 同任务 | 缺陷**定位到方法级**、风险信号分解、四类口径分类（需求缺失/超范围/逻辑不一致/约束不满足） |
| 5. 追溯矩阵 | 「追溯矩阵」页 | 需求↔代码**双向追溯**全覆盖视图 |
| 6. 报告中心 | 「报告中心」 | 一键导出 Word / PDF / Excel 检测报告 |
| 7. 智能体（可选） | 右下角 AI 助手 | 对话式查询分析结果；写操作（如重跑分析、改缺陷状态）需**人工确认**（人机协同安全设计） |
| 8. 管理端（可选） | 管理员登录 | 数据大屏、审计日志（哈希链防篡改）、数据变更日志、备份恢复 |

## 三、常见问题

| 现象 | 处理 |
|---|---|
| backend 启动即退出 | `.env` 缺少 4 个必填密钥之一，补齐后 `docker compose up -d` 重启 |
| 80 / 8080 端口被占用 | 修改 `docker-compose.yml` 端口映射，或停用占用进程（IIS/其他 Java 进程） |
| demo-seed 报"登录失败" | 确认 backend 已就绪（`docker compose ps` 中 backend 为 healthy）且使用默认演示库（`init.sql` 含 demo 账号） |
| LLM 增强无响应 | 「大模型配置」页检查引擎连通性；本地 Ollama 需先 `bash scripts/pull-codellama.sh` 拉取模型 |
| 重置演示数据 | `docker exec -i traceguard-mysql mysql -utraceguard -p"密码" traceguard < scripts/demo-reset.sql` 后重跑 demo-seed |
