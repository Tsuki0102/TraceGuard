# 软件需求-代码一致性验证与缺陷自动检测系统 软件需求规格说明书
**文档版本**：V1.1
**项目名称**：基于形式化需求规约与大模型融合的软件需求-代码一致性验证与缺陷自动检测系统
**编制日期**：2026年06月（V1.0 初稿）／2026年09月（V1.1 依据系统实现现状修订）
**适配环境**：Windows 原生环境、Java 技术栈、B/S 架构（支持桌面与移动端浏览器访问）
**文档密级**：内部公开

## 1 引言
### 1.1 文档目的
本文档完整定义了**软件需求-代码一致性验证与缺陷自动检测系统**的功能需求、非功能需求、接口需求、设计约束与验收标准，是项目研发、模块测试、系统集成、结项验收的核心依据，同时为项目开发团队、测试团队、指导教师及验收评审方提供统一的需求认知基准。

### 1.2 项目范围
本系统面向中小软件企业敏捷开发场景与高校软件工程教学科研场景，聚焦软件开发全流程中「需求与代码不一致」的核心痛点，融合形式化需求规约的严谨性与大语言模型的语义理解能力，实现**自然语言需求自动化形式化建模、Java代码静态解析与语义提取、需求-代码多维度一致性校验、缺陷自动定位与追溯、可视化全流程管理**五大核心能力。
- 适用对象：中小软件企业开发工程师、测试工程师、QA人员、项目经理，高校软件工程专业师生
- 不适用范围：非Java技术栈项目、嵌入式实时系统、超大规模（百万行级）工业软件项目的全量验证

### 1.3 术语定义与缩写
| 术语/缩写 | 全称 | 定义说明 |
|----------|------|----------|
| SRS | 软件需求规格说明书 | 本文档 |
| AST | 抽象语法树 | 代码语法结构的树形表示，用于代码静态解析 |
| CFG | 控制流图 | 代码执行流程的图形化表示，用于代码逻辑还原 |
| Alloy | 轻量级形式化规约语言 | 本项目用于需求形式化建模的核心语言 |
| Kripke结构 | 克里普克结构 | 本项目需求形式化规约的语义基础模型 |
| 双向追溯矩阵 | 需求-代码双向追溯映射表 | 实现需求条目与代码实现的全链路关联追溯 |
| 大创项目 | 大学生创新创业训练计划项目 | 本项目的立项主体 |
| Alloy Analyzer | Alloy 形式化分析求解器 | 本项目集成的官方求解器（6.2.0），基于 kodkod + Sat4j 做真实 SAT 求解，输出 SAT/UNSAT/UNKNOWN/TIMEOUT/ERROR 五态并提取反例 |
| Soot | Soot 静态分析框架 | 用于构建 Java **字节码级**控制流图（CFG），4.7.0 版本；构建失败时回退 AST 级 CFG |
| BGE | BAAI General Embedding | 本地中文语义向量模型，经 ONNX Runtime 离线推理，用于需求/代码语义向量化；模型缺失时回退 TF-IDF |
| TF-IDF | 词频-逆文档频率 | 本地向量化不可用时的降级相似度算法，配合 jieba 中文分词计算余弦相似度 |
| LLM 二审 | 大模型一致性复核判定 | `ConsistencyJudge` 在规则判定之后发起的语义复核，采用双提示词交叉验证与风险仲裁，可覆盖规则判定结果；未配置 LLM 时以规则模式为准 |
| 三维相似度 | Sim = α·Cos + β·Con + γ·Inv | 一致性校验核心公式，融合语义相似度、约束匹配度、不变量满足度，默认 α=0.4、β=0.35、γ=0.25 |
| 缺陷风险惩罚 | Defect Risk Penalty | 静态缺陷信号对相似度得分的加权折减项，权重 0.55，用于抑制带缺陷代码被判为一致 |
| SPI | 服务提供者接口 | 代码解析器（`CodeParser`）与解析器注册表（`ParserRegistry`）的可扩展机制，当前仅注册 Java 实现 |
| WebSocket | WebSocket 全双工通信协议 | 用于分析任务进度的实时推送，握手鉴权通过一次性票据（ticket）完成 |
| 分片上传 | 大文件分块断点续传 | 代码工程/需求文档大文件的分块上传与合并机制 |
| 禅道 / Jira | 第三方项目管理系统 | 缺陷工单双向同步与外部集成的对接对象 |

## 2 总体描述
### 2.1 产品愿景
针对传统人工需求评审效率低、漏检率高，纯大模型需求比对存在幻觉、缺乏严谨性，商用形式化验证工具门槛高、成本高的行业痛点，打造一款**低门槛、全自动化、高严谨性、Windows原生适配**的需求-代码一致性验证工具。通过「大模型自动化形式化建模+形式化模型驱动的一致性校验」技术闭环，让中小软件企业无需专业形式化方法经验，即可实现需求缺陷的前置检测、需求与代码不一致性的自动化识别、缺陷的精准定位与可解释性分析，从根源提升软件交付质量与研发效率。

### 2.2 用户特征
| 用户角色 | 特征描述 | 核心使用需求 |
|----------|----------|--------------|
| 企业开发工程师 | 具备Java开发基础，无形式化方法专业知识，日常负责业务代码开发 | 快速定位代码与需求不一致的问题，获取可落地的缺陷修复建议 |
| 测试/QA工程师 | 具备软件测试基础，负责需求覆盖率验证、缺陷闭环管理 | 批量完成需求-代码一致性校验，输出可追溯的缺陷报告与覆盖率统计 |
| 项目经理 | 负责项目全流程管理，关注项目进度、交付质量与合规性 | 查看项目需求覆盖率统计、缺陷分级统计，满足项目合规审计要求 |
| 高校师生 | 具备软件工程理论基础，用于教学实训与科研工作 | 轻量化完成需求工程、形式化方法、软件质量保障的教学实验与科研验证 |

### 2.4 设计约束
1. **技术栈约束**：全程基于Java核心技术栈开发，后端采用 Java 21 + SpringBoot 2.7.18 + MyBatis-Plus，前端采用 Vue3 + Element Plus + Vite，禁止引入Linux专属依赖组件，保障Windows环境原生适配。
2. **知识产权约束**：所有依赖组件均采用开源合规协议，系统自主研发代码占比不低于90%，产出成果知识产权归属郑州轻工业大学与项目研发团队。
3. **性能约束**：单项目万行级Java代码的全流程分析任务，在普通Windows办公电脑上完成时间不超过10分钟。
4. **易用性约束**：核心操作流程无需用户具备形式化方法专业知识，全流程可视化操作，关键步骤提供引导提示；界面响应式适配，支持手机/平板浏览器访问。
5. **合规性约束**：系统数据处理默认均在**本地**完成，敏感的项目需求文档、代码工程不上传至第三方公有云，保障企业数据安全。
6. **大模型可缺省约束**：大模型为**可选增强**能力，默认关闭（`traceguard.llm.enabled=false`）。未配置 API 密钥时，系统以纯规则模式完整运行全部一致性校验与缺陷检测流程，功能不降级、流程不中断；仅当用户显式配置并启用外部大模型后，相关需求/代码文本才会发送至用户自行指定的服务端点。

### 2.5 假设与依赖
1. 假设用户提供的需求文档为Word（.docx）、PDF、Markdown格式，内容为中文自然语言书写的标准化软件需求。
2. 假设用户提供的代码工程为标准Java项目，以 .zip / .jar / .war 压缩包或批量 .java 文件形式上传，代码语法符合Java开发规范、可被 JDK 编译器（Java 8/11/17 目标版本）成功编译。**说明**：系统通过 `pom.xml` / `build.gradle` 自动探测项目根目录与 Java 目标版本，但**不执行 Maven/Gradle 依赖解析与构建**，因此依赖三方库的代码可能因缺少依赖而编译失败，此类文件将被跳过并记录解析日志，不影响其余文件分析。
3. 大模型为可选依赖：默认以规则引擎运行；启用后依赖 OpenAI 兼容端点可正常访问（DeepSeek / 智谱 GLM / 通义千问云端 API，或本地 Ollama 部署的 CodeLlama 7B）。LLM 判定成功率低于 10% 时系统自动整体回退规则基线，不影响可用性。
4. 依赖 JavaParser 3.25.5、Soot 4.7.0、Alloy Analyzer 6.2.0、ONNX Runtime 1.17.0 等开源组件持续提供稳定的技术支持与版本更新。Soot 在 JDK 17+ 上解析 JDK 类需开放 JDK 模块（`--add-opens`，已内置于构建与启动配置）。
5. 依赖学校校企合作资源与开源仓库（GitHub/Gitee）构建的真实项目数据集，用于算法优化与系统测试；当前评测基于 `samples/dataset/` 自建标注集（规约转换 N=45，一致性标注对 M=55）。
6. 本地 BGE 语义向量模型为可选组件：模型文件存在时启用 ONNX 离线向量化，缺失时自动回退 jieba + TF-IDF 相似度，两种模式均可完成一致性校验。

## 3 具体功能需求
本系统核心功能分为四大模块，分别为**需求预处理与形式化建模模块、代码语义提取与静态分析模块、需求-代码一致性校验与缺陷定位模块、可视化管理平台模块**，各模块功能需求详细定义如下。

### 3.1 需求预处理与形式化建模模块
本模块为系统前置核心模块，实现从非结构化自然语言需求到标准化Alloy形式化规约的全自动化转换，无人工干预。

#### 3.1.1 需求文档导入与解析功能
| 功能编号 | FR-REQ-001 |
|----------|------------|
| 功能名称 | 需求文档导入与结构化解析 |
| 功能描述 | 支持用户导入多格式需求文档，自动完成文档解析、内容提取、结构化处理，输出标准化需求语义单元 |
| 输入 | 1. 用户上传的Word、PDF、Markdown格式需求文档<br>2. 可选的需求分句规则、过滤规则配置 |
| 输出 | 1. 解析后的需求全文本内容<br>2. 结构化拆分后的需求条目列表<br>3. 需求解析日志（含异常内容提示） |
| 业务规则 | 1. 支持单文档/多文档批量导入，单文档大小不超过50MB<br>2. 自动完成需求分句、去重、冗余信息过滤，剔除无业务含义的格式内容<br>3. 自动识别功能需求、非功能需求、约束条件、边界条件，拆分最小需求语义单元<br>4. 对解析失败的文档内容，给出明确的异常原因与修正建议 |

#### 3.1.2 需求语义提取与结构化处理功能
| 功能编号 | FR-REQ-002 |
|----------|------------|
| 功能名称 | 需求语义提取与结构化处理 |
| 功能描述 | 基于大模型语义理解能力，对拆分后的需求语义单元进行深度解析，提取核心业务逻辑、状态定义、约束规则、不变量，为形式化建模提供标准化输入 |
| 输入 | 拆分后的需求语义单元列表 |
| 输出 | 1. 需求语义结构化数据集（含状态集合、初始状态、状态转移关系、原子命题约束、系统不变量）<br>2. 需求约束规则清单<br>3. 需求歧义性检测报告 |
| 业务规则 | 1. 基于Kripke语义模型，将自然语言需求拆解为「状态-转移-约束」的标准化结构<br>2. 自动识别需求中的歧义性内容、矛盾性约束、缺失的边界条件，给出前置优化建议<br>3. 对每个需求语义单元生成唯一标识（需求ID），作为全流程追溯的基准 |

#### 3.1.3 需求形式化规约自动生成功能
| 功能编号 | FR-REQ-003 |
|----------|------------|
| 功能名称 | Alloy形式化规约自动生成 |
| 功能描述 | 将结构化需求语义自动转换为标准化Alloy形式化规约代码，实现需求建模全流程自动化。**生成策略为「规则模板为主 + 大模型增强为可选」**：默认由 `RequirementAnalyzerUtil.generateAlloySpec` 基于 Kripke 语义要素（S/S0/R/AP/L）以确定性模板拼接生成 `sig` / `abstract sig State` / `pred init` / `pred transition` / `fact invariants` / `assert consistencyCheck` / `check ... for 5`；启用大模型后由 `LlmService.generateAlloy` 生成，LLM 不可用或返回为空时自动回退规则模板，保证流程不中断 |
| 输入 | 结构化需求语义数据集（状态集合、初始状态、转移关系、原子命题、不变量）、需求约束规则清单 |
| 输出 | 1. 与需求语义单元对应的Alloy形式化规约代码<br>2. 规约代码与需求条目映射关系表<br>3. 生成引擎标识（规则模板 / 具体大模型） |
| 业务规则 | 1. 自然语言需求到Alloy形式化规约的转换准确率不低于85%（实测：规则基线语义口径 **100.0%**，样本 N=45，达标；详见《评测报告-综合》）<br>2. 生成的Alloy规约代码符合Alloy Analyzer 6.2.0语法规范，可直接用于模型校验<br>3. 支持规约代码的在线查看、编辑与手动优化（Alloy 实验室页面）<br>4. 大模型路径产出的规约须同样通过 FR-REQ-004 校验；历史评测中云端 qwen-max 路径未达标（44.4%），故**不作为默认路径**，仅并列留档供对照 |

#### 3.1.4 形式化规约模型校验与优化功能
| 功能编号 | FR-REQ-004 |
|----------|------------|
| 功能名称 | 形式化规约模型校验与优化 |
| 功能描述 | 基于 **Alloy Analyzer 6.2.0** 完成形式化规约的一致性、完整性校验，自动检测模型中的逻辑矛盾、约束缺失，给出优化建议。采用「**真实语义求解 + 结构/语义降级校验**」双通道：优先调用 `AlloyAnalyzerUtil` 经 kodkod + Sat4j 做真实 SAT 求解；Alloy 不可用时自动降级为 `AlloySpecVerifierUtil` 的结构语法校验与 Kripke 语义校验 |
| 输入 | 生成的Alloy形式化规约代码、需求定义的系统不变量 |
| 输出 | 1. 规约模型一致性校验报告（含求解状态与反例）<br>2. 逻辑矛盾、约束缺失的定位结果与优化建议<br>3. 校验通过的标准化形式化规约模型 |

### 3.3 需求-代码一致性校验与缺陷定位模块
本模块为系统核心创新模块，实现需求与代码的多维度一致性校验、缺陷分级分类、自动定位与双向追溯，是系统核心价值的载体。

#### 3.3.1 多维度语义相似度计算功能
| 功能编号 | FR-CHECK-001 |
|----------|--------------|
| 功能名称 | 需求-代码三维语义相似度计算 |
| 功能描述 | 基于融合语义相似度、约束匹配度、不变量满足度的三维核心公式，完成需求语义单元与代码语义单元的相似度计算，输出标准化相似度结果 |
| 输入 | 1. 需求语义向量、需求约束规则、需求形式化模型不变量<br>2. 代码语义向量、代码约束实现、代码逻辑还原结果<br>3. 权重系数α、β、γ（α+β+γ=1） |
| 输出 | 1. 需求语义单元与代码语义单元的相似度矩阵<br>2. 每个需求-代码对的三维度分项得分与综合相似度Sim(Ri,Cj)结果<br>3. 相似度计算热力图 |
| 业务规则 | 1. 严格遵循核心公式：Sim(Ri,Cj)=α⋅Cos(EmbR,EmbC)+β⋅Con(Ri,Cj)+γ⋅Inv(Ri,Cj)<br>2. 余弦相似度Cos(EmbR,EmbC)：优先采用 BGE 稠密向量余弦并经 (1+cos)/2 归一化；向量化不可用时降级为 TF-IDF + jieba 余弦，取值范围[0,1]<br>3. 约束匹配度Con(Ri,Cj)：由 `RequirementConstraintExtractor` 将需求约束点与代码证据做结构化比对，取值范围[0,1]<br>4. 不变量满足度Inv(Ri,Cj)：由 CFG 结构特征（分支/循环/异常边）布尔匹配与原子命题 AP 满足度综合计算，取值范围[0,1]<br>5. **默认权重 α=0.4、β=0.35、γ=0.25**（α+β+γ=1），可由用户在发起任务时自定义，亦可在系统配置中调整默认值<br>6. **缺陷风险惩罚**：最终相似度 `Sim' = Sim × (1 − defectRisk × 0.55)`，将静态缺陷信号折减计入，抑制带缺陷代码被判为一致<br>7. 启用大模型时，`ConsistencyJudge` 以双提示词交叉验证 + 规则风险仲裁在规则判定之后做**二审**，结果覆盖规则判定；LLM 成功率低于 10% 时整体回退规则基线 |

## 4 接口需求
### 4.1 用户接口
1. 系统采用Web可视化界面，整体布局采用「左侧导航栏+右侧内容区」的经典管理系统布局，操作逻辑符合Windows用户使用习惯。
2. 核心操作路径不超过3次点击，关键功能（任务发起、报告查看、追溯查询）在首页设置快捷入口。
3. 所有异常操作、执行失败、数据校验不通过的场景，均在界面弹出明确的提示信息，包含错误原因与解决方案。
4. 缺陷详情、代码片段、需求原文采用分栏对比展示，支持代码行号与需求条目高亮关联。

### 4.2 软件接口
| 接口名称 | 对接对象 | 接口用途 |
|----------|----------|----------|

| 数据库接口 | MySQL 8.0 | 实现系统用户数据、项目数据、分析结果、配置参数的持久化存储 |

3. 适配本地存储设备接口，支持项目数据、备份文件的本地磁盘存储与外接存储设备导出。

## 5 非功能需求
### 5.1 性能需求
1. **分析效率**：单项目万行级Java代码的全流程分析任务，在推荐配置Windows电脑上完成时间≤10分钟；千行级代码分析任务完成时间≤2分钟。
2. **准确率指标**：自然语言需求到Alloy形式化规约的转换准确率≥85%；需求-代码不一致性缺陷检测准确率≥80%；缺陷漏检率≤15%，误报率≤10%。
3. **并发性能**：支持单用户同时发起最多3个分析任务，多任务并行执行时无系统卡顿、数据错乱问题。
4. **响应性能**：界面操作响应时间≤2秒；列表查询、数据统计响应时间≤3秒；大文件上传支持断点续传，上传速度适配本地网络带宽。
5. **资源占用**：系统运行时CPU占用率≤70%，内存占用峰值≤8GB，不影响Windows系统其他办公软件的正常运行。
6. **实测达成情况（2026-08 批次，详见《评测报告-综合》《性能基准报告-汇总》）**：
   - 需求→Alloy 规约转换准确率（语义口径）**100.0%**（N=45，目标 ≥85%，达标）；
   - 不一致性缺陷检测准确率 **96.4%**、漏检率 **3.8%**、误报率 **3.4%**（LLM 判定口径，标注对 M=55，目标分别为 ≥80% / ≤15% / ≤10%，全部达标）；
   - 主类型判定准确率 **84.0%**（单列指标，不计入漏检）；
   - 规则基线并列留档：准确率 47.3%、漏检率 0.0%、误报率 100.0%，用于对照说明 LLM 二审对误报的抑制效果。

### 5.2 安全性需求
1. **数据安全**：用户上传的需求文档、代码工程、项目数据均存储在本地，未经用户允许不上传至任何第三方服务器；敏感数据采用加密存储，防止数据泄露。
2. **访问安全**：系统采用账号密码认证方式，支持密码复杂度校验、定期修改提醒；用户操作全程留痕，操作日志不可篡改，可追溯。
3. **权限控制**：系统设置管理员、普通用户两级权限，管理员可进行用户管理、系统配置，普通用户仅可操作自身创建的项目数据，实现数据隔离。
4. **代码安全**：系统仅对用户代码进行静态解析与语义分析，不修改、不泄露用户源代码，不植入任何恶意代码。

### 5.3 易用性需求
1. **学习成本**：用户无需具备形式化方法专业知识，经过30分钟培训即可独立完成全流程操作；系统提供操作手册、功能引导视频、新手引导流程。
2. **操作便捷性**：核心流程「项目创建→需求上传→代码上传→分析发起→报告查看」支持一键式操作，无需复杂参数配置，默认参数适配绝大多数场景。
3. **容错性**：支持用户误操作的撤销与恢复；任务执行过程中支持断点续跑，避免因系统异常导致分析任务重新执行；文档/代码解析失败时，不影响其他正常文件的分析流程。
4. **可解释性**：所有一致性判定结果、缺陷分析结果均给出明确的原因与依据，禁止无理由的黑盒判定，保障用户可理解、可验证。

### 5.4 可靠性需求
1. **系统稳定性**：系统连续运行无故障时间≥72小时；平均无故障时间（MTBF）≥30天；系统崩溃后可快速恢复，数据不丢失。
2. **容错能力**：针对用户上传的非标准格式文档、存在语法错误的代码、异常参数配置，系统可正常捕获异常，给出友好提示，不会出现系统崩溃、数据错乱问题。
3. **数据可靠性**：项目分析结果、配置数据、用户数据存储完整率100%，无数据丢失、损坏问题；支持数据定时自动备份与手动备份，备份数据可100%恢复。

### 5.5 兼容性需求
1. **操作系统兼容性**：原生适配Windows 10 21H2及以上、Windows 11全系列64位操作系统，无兼容问题。
2. **浏览器兼容性**：桌面端适配 Chrome 100+、Edge 100+、Firefox 100+；移动端适配 **iOS Safari**（iOS 15+）与 **Android Chrome**（100+），响应式布局，核心功能完整可用。
3. **Java版本兼容性**：支持 Java 8、Java 11、Java 17 LTS 版本的项目代码解析（通过 `pom.xml` / `build.gradle` 自动探测目标版本）。
4. **项目结构兼容性**：支持标准 Maven、Gradle 项目结构（单模块/多模块），以 .zip / .jar / .war 压缩包或批量 .java 文件形式上传；通过 pom.xml / build.gradle 识别工程根目录与 Java 目标版本（**不执行依赖解析与构建**）。

### 5.6 可维护性与可扩展性需求
1. **模块化设计**：系统采用高内聚、低耦合的分层架构，四大核心模块相互独立，可单独升级、优化、替换，不影响其他模块功能。
2. **可配置性**：系统核心参数（权重系数、相似度阈值、解析规则、模型参数）支持可视化配置，无需修改代码即可完成参数调整。
3. **可扩展性**：已落地基于 **SPI 的可扩展机制**——代码解析侧提供 `CodeParser` 接口与 `ParserRegistry` 注册表（切换 `traceguard.analysis.code-language` 即可接入新语言），规约侧通过 `traceguard.analysis.spec-language` 预留扩展。**当前已实现**：Java 代码解析、Alloy 规约；C#、Python、TLA+ 等**尚未实现**，待新增对应实现 Bean 后即可启用。
4. **可测试性**：系统各模块均提供独立的测试接口，支持单元测试、集成测试、性能测试的自动化执行。

1. 系统采用MySQL 8.0关系型数据库进行结构化数据存储，采用本地文件系统存储用户上传的需求文档、代码项目、备份文件。

3. 数据库表设计遵循第三范式，减少数据冗余；核心查询字段建立索引，提升查询效率。
4. 历史项目归档数据支持压缩存储，降低磁盘空间占用。

### 6.3 数据备份与恢复需求
1. 系统支持手动数据备份与定时自动备份，自动备份频率支持用户自定义（每日/每周/每月）。
2. 备份文件包含系统全量用户数据、项目数据、配置数据，采用加密压缩格式存储。
3. 支持备份文件的一键恢复，恢复后系统数据与备份时间点完全一致，无数据丢失、错乱。
4. 系统异常重启后，自动进行数据完整性校验，对损坏的数据进行修复，保障数据一致性。
