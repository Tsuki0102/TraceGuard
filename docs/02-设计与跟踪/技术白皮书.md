# TraceGuard 技术白皮书（V1.2）

> 对应 SRS 7.3 成果验收「技术白皮书」要求。本文档面向评审与教学科研场景，阐述系统技术路线、核心算法、创新能力与实测指标。

---

## 1. 背景与定位

软件需求与代码「不一致」是导致缺陷、返工与合规风险的核心源头。TraceGuard 面向中小软件企业与高校教学科研，融合 **形式化需求规约的严谨性** 与 **大语言模型的语义理解能力**，提供从需求文档到 Java 代码的全流程一致性验证与缺陷自动检测，降低形式化方法的使用门槛。

---

## 2. 技术路线

| 阶段 | 技术 | 说明 |
|---|---|---|
| 需求解析 | Apache POI / PDFBox / CommonMark | 多格式文档解析 + 内容清洗（页眉/页脚/页码/目录/表格线残留剔除） |
| 需求形式化 | Kripke 五元组 + Alloy Analyzer | 状态/迁移/约束/不变量结构化提取，自动生成 Alloy 规约并求解校验 |
| 代码解析 | JavaParser（AST）+ Soot（CFG） | 类/方法/字段级 CodeUnit 拆分，Java 8/11/17 分版本适配，降级链保稳 |
| 逻辑还原 | LLM（可选增强）+ 规则 fallback | 代码方法中文逻辑描述，多引擎可切可回退 |
| 一致性校验 | 三维相似度模型 | 语义/约束匹配/不变量满足度加权，T1/T2 三级分级 |
| 缺陷检测 | 规则 + LLM 二审 | 4 类主类型 + 子类型，方法级定位，精准到代码行号 |
| 可视化 | Vue3 + Element Plus + ECharts | 全流程管理、统计图表、质量趋势、双向追溯矩阵 |

## 3. 核心算法：三维相似度一致性校验

**Sim(Rᵢ, Cⱼ) = α·Sem(Rᵢ, Cⱼ) + β·Con(Rᵢ, Cⱼ) + γ·Inv(Rᵢ, Cⱼ)**

- **α 语义相似度**（默认 0.4）：Embedding 向量余弦 + 关键词 Jaccard 增强（本地 BGE ONNX 离线可用，免密钥）
- **β 约束匹配度**（默认 0.35）：空值校验、参数验证、异常处理、日志等约束实现识别
- **γ 不变量满足度**（默认 0.25）：返回值、语法正确性、访问修饰符等不变量满足

**分级判定**（对齐 SRS FR-CHECK-002 与代码实际行为）：`Sim > T1` 完全一致；`T2 ≤ Sim ≤ T1` 一般不一致；`Sim < T2` 严重不一致。阈值前端可配，生产默认 T1=0.80/T2=0.50（application.yml）；《阈值标定报告》（2026-08-26 批次，标定链路参数 α/β/γ=0.2/0.55/0.25）推荐 t1=0.46 / t2=0.33（本数据集缺陷检测准确率最优 52.7%）——两者关系见报告结论节。

**双路径口径（FUN-08，如实声明）**：Con/Inv 维度按数据可得性分两条路径——

| 路径 | 触发条件 | 实现 |
|---|---|---|
| 规约驱动严格路径 | 存在 Alloy 规约 + 代码 CFG 数据 | Con/Inv 由「需求约束点 × 代码实现证据」结构化比对（GAP-046/GAP-005，需求约束点缺失时代码未实现证据则得分显著下降） |
| 启发式降级路径 | 无规约/无 CFG，或需求无可提取约束点（多为英文/无明确约束语义） | Con/Inv 均回退**中性 0.5**（FUN-13/FUN-08②：无约束点需求无法评估约束实现，中文关键词兜底无区分度已移除，与 Inv 对称，避免无关联英文需求被 con/inv 高估而主导匹配排序）；核心评分在无 Alloy 规约场景以启发式为主，与「形式化严谨性」宣传的口径差异已如实标注 |

> 适用建议：正式评审/关键项目请为需求提供/生成 Alloy 规约以走严格路径；无规约场景的结果应视为启发式评估而非形式化证明。

## 4. 缺陷精准定位（2.6 整改）

`ConsistencyChecker.locateDefectLine` 按缺陷子类型（状态/数值越界/约束校验关键词优先，兜底方法首行）从代码证据匹配具体行，叠加 `CodeUnit.startLine` 得源文件绝对行号；前端红色高亮命中行，缺陷清单 Excel 含行号列。

---

## 5. 创新点

1. **形式化 + LLM 双引擎融合**：规则保底、LLM 增强，本地 CodeLlama/Ollama 真集成（LangChain 编排，可回退），不开源密钥即可运行。
2. **方法职责边界判定原则**：LLM 二审仅判当前方法自身职责，避免把相邻方法/其他环节缺失误判给当前方法，显著降低误报。
3. **协作式任务控制**：暂停/恢复/终止在四个长耗时 LLM 批次循环逐 item 插入控制检查点，响应延迟低。
4. **安全合规**：数据全程本地处理，审计日志哈希链防篡改，字段级数据变更日志可追溯 diff，加密备份恢复。
5. **可扩展架构**：SPI 预留多语言（C#/Python）/多形式化语言（TLA+）扩展点。
